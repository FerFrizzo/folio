# Releasing Folio

One command bumps the version, builds iOS + Android, and submits to both stores.

```bash
npm run release          # patch: 1.0.2 → 1.0.3
npm run release:minor    # minor: 1.0.2 → 1.1.0
npm run release:major    # major: 1.0.2 → 2.0.0
```

Each command runs, in order:

1. **`preflight`** — tsc, lint, tests, expo-doctor, and the Cloud Functions
   build/tests. If anything fails, nothing is bumped or built.
2. **`npm version <level>`** — bumps `version` in `package.json`, commits it, and
   creates a git tag `vX.Y.Z`.
3. **`eas build --platform ios --profile production --auto-submit`** — builds iOS
   and submits to App Store Connect. (Android is intentionally excluded; run
   `eas build --platform android --profile production` manually if you need it.)

## Why the bump is automatic

The App Store closes a "version train" once a marketing version is approved, so
resubmitting under the same version fails with:

- **90186** — "the train version '1.0.1' is closed for new build submissions"
- **90062** — "CFBundleShortVersionString … must contain a higher version than
  the previously approved version"

Baking `npm version` into `release` means every submission ships a higher
`CFBundleShortVersionString`, so these errors can't happen.

## Single source of truth

The marketing version lives **only** in `package.json`. `app.config.ts` imports
it (`version: pkg.version`), and `app.config.test.ts` fails the build if the two
ever drift. Don't hardcode a version in `app.config.ts`.

## What you don't manage

- **Build number** (`CFBundleVersion` / `versionCode`) is auto-incremented by EAS
  (`appVersionSource: "remote"` + `autoIncrement: true` in `eas.json`). You never
  set it by hand.
- The stale versions in `ios/` and `android/` are ignored — those dirs are
  gitignored and regenerated by `expo prebuild` from `app.config.ts`.

## Prerequisites

- A **clean git working tree** — `npm version` refuses to run otherwise. Commit
  your work first. This also keeps each release on its own tagged commit.
- Logged in to EAS (`eas login`) with submit credentials configured (already set
  under `submit.production` in `eas.json`).
- **Dependencies aligned with the Expo SDK.** `preflight` runs `expo-doctor`,
  which fails if any package drifts from the version the SDK expects (a common
  "patch version mismatch"). When it flags packages, run:

  ```bash
  npx expo install --fix   # bumps the flagged packages to the SDK's expected versions
  ```

  Commit the resulting `package.json` / `package-lock.json` changes. Run this in
  your normal shell, not a sandboxed/offline one, so the install completes
  cleanly.

## After a successful release

Push the release commit and tag:

```bash
git push --follow-tags
```
